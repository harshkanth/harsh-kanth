# About

![Illustration of Harsh Kanth with his six dogs in a garden](assets/images/harsh-kanth.webp){ .portrait loading=lazy }

<p class="lead">I'm Harsh Kanth. For more than ten years, I've helped companies explain their products clearly, from SAP enterprise software to Microsoft's developer platform to startups writing their first help center.</p>

Today I work as an SAP consultant and technical writer, consult on documentation for identity and enterprise software teams, and run [Becdeg](https://becdeg.com), the company behind the [Docifice](https://docifice.com) documentation agency.

My work covers the whole documentation lifecycle: planning the information architecture, writing and testing the content, setting the style, building the publishing pipeline, and keeping it all current release after release.

## What I believe about documentation

**Documentation is part of the product.** Users meet it at the moments that decide whether they succeed: installing, configuring, recovering from an error. It deserves the same care as the interface.

**Terminology is a design decision.** Most confusing documentation isn't badly written; it uses three words for one thing. Agreeing on terms early saves every reader time later.

**Structure beats volume.** A smaller set of well-organized, task-focused topics helps more than a large set of pages nobody can navigate.

**Docs should be easy to maintain.** Version control, templates, and content reuse keep documentation accurate long after the first release.
