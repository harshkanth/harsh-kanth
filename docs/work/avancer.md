## The challenge

Avancer's documentation had grown product by product, with each guide developing its own habits and living in Microsoft 365. Identity governance products also have several distinct readers: IAM administrators who install and configure, application owners who respond to onboarding requests, and buyers who need to understand the value first. Every document had to describe the same products in the same words.

### Migration from Microsoft 365 to Confluence

I moved the product documentation out of Microsoft 365 and set up the Confluence Cloud space: a clear page structure, branded PDF exports that match the Word templates, and a consistent space-wide footer. Identity Bridge documentation, including its user and connector guides, now lives and is maintained there.

### A house style guide and governance

- **Avancer Style Guide v2.0**, covering tone and voice, how to address the reader, American English, parallel construction, procedure and troubleshooting structure, and release note conventions
- **A visual identity and callout system** for documents: heading hierarchy, numbered sections at every level, and consistent note, tip, and warning callouts
- **Compliance passes** across release notes, user and connector guides, an Oracle to SQL Server migration guide and playbook, a TLS configuration guide, and installation, admin, and user guides
- **A seven-document set for NELM**, a non-employee lifecycle management product: installation, configuration, development, and design documents, testing evidence, and a product brief

A few of the style decisions:

| Topic | Rule |
|-------|------|
| Abbreviations | "for example" instead of "e.g.", "and so on" instead of "etc." |
| Lists | Oxford comma, parallel construction in every list |
| UI actions | "click" for buttons and links, "select" for options and values |
| Inclusive terms | "allowlist" and "blocklist" |
| Release notes | "Improved" instead of "Fixed", with a consistent structure per entry |

## How I approached it

### One home for the documentation

Moving to Confluence gave the documentation a single home and page structure, which made it practical to apply the style guide and templates across the whole set instead of file by file.

### One product, several readers

Each document in the Onboarding Hub suite maps to a single role and a single job. Admin content covers configuration, owner content covers responding to requests, and the architecture document carries the technical depth. Cross-references connect them instead of repeating content.

### Prerequisites that remove guesswork

Integration setup is where onboarding usually stalls, so each discovery source and AI provider has its own prerequisites topic with the exact permissions, credentials, and settings to have ready before installation starts.

### A clean rename

When the product was renamed from IARP to IGA Application Onboarding Hub, I carried the change through every document, file name, and caption in one controlled pass, so no customer-facing material used two names.
