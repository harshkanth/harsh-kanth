# Documentation overhaul across four companies

<p class="lead">Vision Group runs four subsidiaries across retail technology, AI/ML, and AR/VR. As document owner reporting to the Chief Product Officer, I rebuilt how all four companies created, stored, and reused documentation.</p>

## The challenge

Each subsidiary had grown its own documentation in its own place, with no shared templates or terminology. The same concepts were written several times in slightly different ways, content was hard to find, and every new document started from a blank page.

## What I delivered

- **A documentation process** with templates, styles, and a style guide used across all four subsidiaries
- **A taxonomy** that organized documentation by product and audience
- **A migration** of siloed content into a CMS and Git repositories
- **Content reuse** so shared concepts were written once and used across products
- **New documentation** for applications, servers and portals, and in-house AI software: SDK guides, API references, step-by-step feature guides, and release notes
- **Leadership** of a team of technical writers and business analysts

## How I approached it

- **Standardize first, then write.** Templates and a shared style came before new content, so everything written afterwards was consistent by default.
- **Reuse instead of rewrite.** Shared topics saved time and kept product descriptions aligned across the subsidiaries.
- **Make content findable.** Moving documentation into a structured CMS and Git made it discoverable and easier to maintain.

## What this shows

- Documentation architecture at an organizational level
- Change management: introducing new tools and process to several teams at once
- Owning documentation strategy with direct accountability to product leadership
