# RPA documentation, docs as code

<p class="lead">EXL's iBOT robotic process automation platform had no online documentation. I proposed moving to a docs-as-code portal, then wrote the documentation from scratch and published it with Markdown, GitHub, and MkDocs.</p>

## The challenge

An automation platform changes with every release, and documentation kept in static files falls behind quickly. Developers and QA teams needed a single place to find current workflows, integration steps, and troubleshooting, and the documentation had to be easy for engineers to review and update.

## What I delivered

- **The proposal and the platform**: an online documentation portal built on Markdown, GitHub, and MkDocs, replacing static documents
- **User manuals and troubleshooting guides** for the iBOT RPA applications
- **Workflow and integration documentation** for automation, orchestration, and process management, written with the RPA development team
- **Reviews and edits** of content written by other team members, for quality and consistency
- **Knowledge transfer sessions** on RPA concepts, documentation practice, and the new toolchain

## How I approached it

- **Put docs where the code lives.** Markdown in Git means documentation changes go through the same pull request review as code, and engineers can suggest fixes directly.
- **Write with the engineers, not after them.** I worked alongside developers, QA, and project managers so procedures were confirmed against the product before publishing.
- **Leave the team self-sufficient.** The KT sessions meant the portal could be maintained after my contract ended.

## What this shows

- Choosing and setting up the right documentation platform, not just writing for one
- Building a documentation set from zero under a short timeline
- Docs-as-code fluency: Git workflows, Markdown, and static site generators. This portfolio runs on the same stack.
