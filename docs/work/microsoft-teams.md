## The challenge

Authentication is where many Teams app projects stall. Developers have to coordinate an app registration in Microsoft Entra ID (then Azure AD), the Teams app manifest, and code in their bot, and a single mismatched value breaks the flow with an unhelpful error. The documentation needed to make a multi-system setup feel linear.

## What I delivered

- **The Add Authentication section** of the Microsoft Teams developer documentation, including single sign-on for bots
- **Developer-focused topics** written with engineers, product managers, and subject matter experts on the Teams platform team
- **Testing of documented procedures** against the product, so every step works as written
- **Proofreading, QA, and SEO** for published content, aligned with the Microsoft Writing Style Guide

## How I approached it

- **Follow the developer's order of operations.** Topics move from registering the app, to configuring the manifest, to writing code, so readers never need a value they haven't created yet.
- **Test what's written.** I ran the procedures myself and wrote down the exact values and settings that worked, rather than relying on specifications.
- **Write to the house style.** Microsoft's style guide favors direct, conversational instructions. Consistency with the rest of Microsoft Learn means developers trust the page immediately.
